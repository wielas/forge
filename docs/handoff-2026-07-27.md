## Decisions taken this session

### D1 — Worker lanes are Hermes profiles, not an external puller `[D]`

ADR-0005 claims "the dispatcher skips cards whose assignee is not a Hermes
profile, so CLI tools pull them instead." Current Hermes docs say the opposite:
workers are dispatcher-spawned Hermes profiles driving the board through a
`kanban_*` tool surface, and an **unknown assignee name fails to spawn**; after
`kanban.failure_limit` (default 2) consecutive failures the dispatcher
**auto-blocks the card**. So `--assignee codex-worker` does not create an
external lane — it creates a card that blocks itself on the second tick, while
`lanes/codex-worker.sh` races the dispatcher for the same rows.

**Target shape:** a Hermes profile (`forge-codex-lane`) whose only job is: read
the card → shell out to `codex exec` in the worktree workspace → verify green →
push + PR → `kanban_complete` with metadata. Hermes then owns claim,
crash-reclaim, retries, circuit breaking, worktree lifecycle, logs, heartbeats
and the dashboard. `kanban-codex-lane` is already a bundled skill on this
install — check it before writing anything new.

**Deletes when implemented:** `lanes/codex-worker.sh` (all four `board_*` VERIFY
functions), most of `hermes/board-bootstrap.sh`.

### D2 — Codex implements, Claude judges, and no metered implementation `[D]`

ADR-0004's Lane C ("metered strong model") is dead. Operator constraint: **no
pay-per-use API tokens in the Forge.** The judge becomes two tiers:

- **Tier 1, unattended, near-free:** `forge-prejudge` profile runs
  `codex exec --output-schema <verdict schema>` on the PR diff with fresh
  context. Only job: bounce the obvious — CI red, scenario theater, diff outside
  `Touches`.
- **Tier 2, attended, subscription:** surviving PRs queue as judge cards, the
  digest pings, the operator taps `/judge` in Claude Code from desk or phone.
  Full rubric, strongest model, zero marginal cost — and it matches the stated
  involvement level ("judge report + spot-checks") rather than fighting it.

Auto-merge stays as decided: judge-approved **and** tagged low-risk at roadmap
time merges unattended; everything else waits for a human tap.

### D3 — The money invariant becomes a gate, not a wish `[D]`

Rule: *no metered tokens for implementation or deep review. OpenRouter aux calls
(Hermes routing, the `/goal` judge) are the only sanctioned metered surface and
stay bounded.* Enforced by a lane precondition that fails when
`ANTHROPIC_API_KEY` or `OPENAI_API_KEY` is present in the worker env —
`scripts/preflight.sh` §2 already checks this. Route the goal judge to a cheap
model via `auxiliary.goal_judge` rather than letting it inherit the main model.

## Handoff blockers, in order

1. **The Forge is not a git repo.** `/retro` proposes PRs against it and the
   mini needs something to clone. `git init`, first commit, push to
   `github.com/wielas/<name>`, then clone on the mini.
2. **`scripts/preflight.sh` has never run on the mini.** Every FAIL it reports
   is a night-run failure that would otherwise happen at 2am.
3. **None of the `forge-*` profiles exist yet.** Cards assigned to a
   non-existent profile auto-block after two ticks (D1).
4. **The heartbeat/timeout pattern is unwritten.** No lane skill exists.
5. **Curator vs symlinked skills `[A]`.** Hermes now runs a curator that
   reviews, archives and rewrites agent-managed skills. `install.sh` symlinks
   git-tracked Forge skills into that directory. If the curator can edit through
   the symlink, methodology drifts outside version control, silently. Settle
   this **before** running `install.sh` on the mini.

## Open design threads (unresolved, worth arguing)

- **Seven ceremonies or five?** `start-chunk` and `end-chunk` are always run
  back-to-back by the same worker; the split may be ceremony without payoff.
- **Copier template vs `forge graft`.** `templates/python-service` only helps
  Python projects and the operator's project list is not. A skill that grafts the
  gate layer (Makefile + lefthook + CI + AGENTS.md) onto *any* repo may serve
  pain-point #1 better than N templates.
- **Does `kanban specify` replace part of `/scope` + `/roadmap`?** Overlapping
  responsibility; decide which owns triage→spec.
- **Skill distribution:** a proper Claude Code plugin could carry skills, agents
  and hooks together and drop the symlinks for that harness — at the cost of
  ADR-0002's write-once portability.
