# Forge audit — 2026-07-27 (verified)

Supersedes the same-day reasoned draft. Every finding below was re-derived against the
live substrate: Hermes 0.19.0 source (`~/.hermes/hermes-agent`), Codex 0.145.0 sandbox
behaviour measured in a throwaway lab under `$HOME`, the four live `forge-*` profile
configs, and a freshly stamped `templates/python-service` taken through `make setup` and
`make check`. No implementation, card creation, push, or `~/.hermes` edit was performed.

## How to read this

Every finding carries a **status** and ends with an **Assert** — the command whose output
changes when the finding is fixed. A finding without an executable assertion is a finding
we cannot prove we closed, which is the failure mode this repo exists to prevent.

| Status | Meaning |
|---|---|
| `measured` | A command was run in this session and its output is quoted. |
| `read` | Read directly from installed source or a live config file. |
| `assumed` | Reasoned from the above; not independently executed. |

**Severity = how soon this stops a run × how much else it causes.** A future upgrade risk
is not a P0 no matter how alarming. The root cause of four other findings is not a P2.

## Verdict

1. Forge cannot complete the hello-chunk today. Five independent P0s block it, and each
   fails at a different stage — board resolution, worktree setup, `make check`, review launch.
2. The methodology layer is sound. The template stamps green, the chunk contract is a real
   contract, the rubric is specific, and the ADRs reason honestly, including about their own
   weakest decisions.
3. What is missing is not more design. It is the thing the design keeps recommending to
   everyone except itself: an executable gate. See **S1**.

## P0 — blocks the first real run

### F1 — A new board has no worktree anchor; the first card auto-blocks on tick 1

- **Evidence (`read`)** — `hermes_cli/kanban_db.py:6368-6408`. With `--workspace worktree`
  and no `workspace_path`, `_resolve_worktree_workspace` reads the board's
  `default_workdir` and **raises** when it is unset. `hermes/board-bootstrap.sh:36` creates
  the board without `--default-workdir` (the flag exists — `hermes kanban boards create
  --help`) and `create_card` (lines 45-53) passes a bare `--workspace worktree`.
- **Consequence** — worse than "fails to start". The dispatcher catches that raise into
  `_record_spawn_failure` (`kanban_db.py:8393`), and `board-bootstrap.sh:51` passes
  `--max-retries 1`, so the card is **auto-blocked on the first dispatch tick**. The
  operator sees a blocked card with no worker output and no obvious cause.
- **Correction** — in `board-bootstrap.sh`, after `boards create`:
  `hermes kanban boards set-default-workdir "$BOARD" "$(git rev-parse --show-toplevel)"`,
  and fail the script if the readback is null. (`hermes project` binding does the same via
  `_sync_board_default_workdir`, `projects_cmd.py:317` — either is fine, but pick one.)
- **Assert**
  ```bash
  hermes kanban boards list --json \
    | jq -e --arg b "$BOARD" '.[]|select(.slug==$b)|.default_workdir|test("^/")'
  ```

### F2 — The lane protocol inverts worktree ownership

- **Evidence (`read`)** — `kanban_db.py:8388` resolves *and materialises* the worktree
  (`_ensure_git_worktree`) **before** `_spawn` at line 8405. The worktree always exists,
  on the right branch, when the worker starts. But `skills/forge-lane/SKILL.md:41` states
  *"A `worktree` workspace is created **worker-side**, so it may not exist yet"* and gives a
  fallback `git worktree add`. `docs/hermes-field-notes.md` repeats the same claim.
- **Consequence** — the fallback is not merely dead code. A worker that takes the branch
  will run `git worktree add … -b <branch>` against a branch already checked out in that
  exact worktree, which fails; the lane then has no recovery path and exits without a
  terminator, which is reaped as `crashed` and ticks the failure counter. This is precisely
  the "crashed means model problem, not skill text" claim in `README.md:122` being wrong.
- **Correction** — delete the fallback block from `forge-lane` §2; replace with
  `cd "$HERMES_KANBAN_WORKSPACE"` and a hard failure if it is not a git checkout. Correct
  the "created worker-side" line in `hermes-field-notes.md`.
- **Assert**
  ```bash
  ! grep -q 'worktree add' skills/forge-lane/SKILL.md
  grep -q 'created .*dispatcher-side' docs/hermes-field-notes.md
  ```

### F3 — Live `terminal.timeout=180` kills the lane's own verification step

- **Evidence (`measured`)**
  ```
  $ hermes -p forge-codex-lane config get terminal.timeout
  180
  $ hermes -p forge-prejudge   config get terminal.timeout
  180
  ```
  `hermes/config-snippets.yaml:49` documents `1800`.
- **Consequence** — narrower and sharper than "the timeout is wrong". `codex exec` is
  already safe: `forge-lane` §3 runs it with `background=True` and polls. The kill lands on
  `forge-lane` §4, `make check`, which runs **synchronously** and on any real chunk exceeds
  180s. The lane dies after the code is written and before it is verified — the most
  expensive possible place to fail.
- **Correction** — set it per profile, not on the default profile, because that is where
  workers read it: `hermes -p forge-codex-lane config set terminal.timeout 1800`. Do the
  same for `forge-prejudge`. Then make `profiles-bootstrap.sh` set it (see **F7**).
- **Assert**
  ```bash
  for p in forge-codex-lane forge-prejudge; do
    [ "$(hermes -p $p config get terminal.timeout)" -ge 1800 ] || exit 1
  done
  ```

### F4 — Tier-1 review cannot launch: the output schema does not exist

- **Evidence (`read`)** — `hermes/profiles/forge-prejudge.SOUL.md:18` instructs
  `codex exec --output-schema <verdict schema>`. That is a literal unresolved placeholder.
  No JSON Schema file exists anywhere in the repo; `rubrics/judge-rubric.md` is Markdown
  containing an illustrative JSON *object*, which `--output-schema` cannot consume.
- **Consequence** — every prejudge run fails at its central step, on every card.
- **Secondary (`read`, lower severity than the draft claimed)** — ADR-0004 D4.1 assigns
  tier 1 to `claude -p`; the SOUL invokes `codex exec`. This is drift, not a design fork:
  ADR-0007 D7.4 already names both engines' flags correctly (`--output-schema` /
  `--json-schema`, both verified present in the live CLIs). Fixing it is a one-word edit,
  not an engine decision — do not re-litigate the lane design over it.
- **Correction** — add `rubrics/judge-verdict.schema.json` as a real JSON Schema generated
  from the `forge.judge.v1` shape in `rubrics/judge-rubric.md`; reference it by absolute
  path (`~/.forge/rubrics/…`, which `install.sh` already symlinks) in the SOUL. Pick the
  engine ADR-0004 names, or amend ADR-0004.
- **Assert**
  ```bash
  jq -e 'has("$schema") and has("properties")' rubrics/judge-verdict.schema.json
  ! grep -q '<verdict schema>' hermes/profiles/forge-prejudge.SOUL.md
  ```

### F5 — Documentation is executable, and it currently contradicts the CLIs

*Ranked P0 because four findings below (F8, F10, F13, and half of F4) are its symptoms.
The draft rated this P2 and its own downstream symptoms P0, which inverts the repair order.*

- **Evidence (`measured`/`read`)** — same repo, contradicting itself:
  - `skills/roadmap/SKILL.md:52` emits `--body-file`; `hermes kanban create --help` has
    `--body` only; `hermes/board-bootstrap.sh:23` **already documents this in a comment**.
  - `README.md:38` and `:48` say Hermes reads skills "via symlinks"; commit `94a850e` and
    `install.sh`'s own header say `skills.external_dirs`.
  - `README.md:50` says "the seven ceremony skills"; there are eight.
  - `README.md:101` — "Everything else in this repo is verified."
  - `README.md:122` — "a `crashed` reap … is a model problem, not a skill-text problem."
    Refuted by **F2**, where skill text causes exactly that reap.
  - All 8 skill descriptions are 134–164 chars against the stated ≤60 preference
    (`README.md:142`).
- **Consequence** — a fresh-context model executes these files. `--body-file` is not a
  documentation nit; it is a bad instruction shipped to a machine. Twelve same-day commits
  correcting claims that were reasoned rather than measured is the observable cost.
- **Correction** — every load-bearing claim gets a status marker (`measured` / `read` /
  `assumed` / `planned`) and a date. Anything `assumed` may not appear in a skill body,
  because skill bodies are executed. Delete or mark superseded prose; keep one operator path.
- **Assert** — see **S1**; this finding is unclosable by prose and is the reason S1 exists.

## P1 — degrades or silently corrupts unattended work

### F6 — The review card is created before CI can possibly exist

- **Evidence (`read`)** — `forge-lane` §6 creates the prejudge card immediately after
  `gh pr create` in §5. `forge-prejudge.SOUL.md:25` then asserts *"CI is green or this card
  would not exist"* and instructs bouncing on `ci-red`.
- **Consequence** — prejudge reads a PR whose checks are queued. It either bounces every
  card on a false `ci-red`, or its most reliable signal is decorative.
- **Correction** — either have the lane wait (`gh pr checks --watch` before §6) or have
  prejudge wait (`gh pr checks <n> --watch --interval 30`), and treat *pending* as a distinct
  third state from green and red. Waiting in prejudge is preferable — it keeps the lane's
  terminator prompt.
- **Assert**
  ```bash
  grep -qE 'gh pr checks .*--watch' hermes/profiles/forge-prejudge.SOUL.md
  grep -q 'pending' hermes/profiles/forge-prejudge.SOUL.md
  ```

### F7 — Runtime configuration cannot be rebuilt from version control

*The most important finding for the stated goal of a durable, self-upgrading system.*

- **Evidence (`measured`)** — the four live profile configs contain `model.default`,
  `toolsets:`, and `skills.external_dirs`. `hermes/profiles-bootstrap.sh` **prints all
  three for manual pasting** and sets none of them: models are set only when
  `FORGE_MODEL_ROUTER`/`FORGE_MODEL_DRIVER` are exported (both default empty, line 32-33),
  and toolsets/external_dirs are `echo`ed (lines 87-88, and `install.sh`'s Hermes section).
  The script also runs `set -uo pipefail` **without `-e`** (line 16).
- **Consequence** — the live state was hand-assembled and the script cannot reproduce it. A
  rebuild, a second mini, or a `hermes update` that resets a key leaves no path back except
  an operator's memory. A system that cannot rebuild its own runtime from git is not
  self-upgrading; it is a hand-tuned machine with documentation attached.
- **Correction** — `profiles-bootstrap.sh` becomes idempotent and total: write
  `config.yaml` from a template per profile (YAML lists included — `hermes config set`
  provably cannot write them, `hermes-field-notes.md`), set `terminal.timeout` and
  `skills.write_approval` per profile, add `set -e`, and re-read every value back. Demote
  `config-snippets.yaml` to `config-examples.yaml` until it is applied by something.
- **Assert**
  ```bash
  ./hermes/profiles-bootstrap.sh --dry-run | grep -q 'terminal.timeout'
  # and: rm -rf a scratch HERMES_HOME, re-run, diff the resulting config.yaml against git
  ```

### F8 — The local enforcement tier installs nothing, on every fresh project

- **Evidence (`measured`)** — stamped `templates/python-service` and ran `make setup`:
  ```
  uv run lefthook install
  error: Failed to spawn: `lefthook`
    Caused by: No such file or directory (os error 2)
  lefthook not installed globally; uv tool install lefthook
  ```
  `lefthook` is absent from `[dependency-groups] dev` in `pyproject.toml.jinja`; the
  template `Makefile` swallows the failure with `|| echo`.
- **Consequence** — stronger than "sometimes swallowed": on a clean machine this fails
  **100% of the time**, so every fresh Forge project ships with **zero git hooks**. ADR-0003's
  entire local enforcement tier — pre-commit fmt/lint, pre-push no-main-push, pre-push
  `make check` — is currently aspirational. Everything that "must hold" holds only in CI.
- **Not a defect, for the record (`measured`)** — the template itself is sound. A fresh
  stamp runs clean: `1 passed`, `Required test coverage of 85% reached. Total coverage:
  100.00%`, `FORGE CHECK: GREEN`.
- **Correction** — add `lefthook` to the dev dependency group, drop the `|| echo`, and let
  `make setup` fail loudly when hooks cannot be installed. ADR-0003's own logic demands it:
  a gate that silently declines to install is prose.
- **Assert**
  ```bash
  make new NAME=probe-$$ DEST=/tmp && cd /tmp/probe-$$ && make setup \
    && test -f .git/hooks/pre-push && grep -q lefthook .git/hooks/pre-push
  ```

### F9 — `end-chunk` writes to `.git/`, which is impossible in both lanes

*Promoted out of the draft's finding 3, where it was a sub-clause of an upgrade risk.*

- **Evidence (`measured`)** — two independent, deterministic failures:
  ```
  # codex sandbox, normal repo, -s workspace-write:
  $ printf 'hello' > .git/PR_BODY.md
  zsh:1: operation not permitted: .git/PR_BODY.md

  # linked worktree — .git is a FILE, not a directory:
  $ file ../wt-test/.git
  ../wt-test/.git: ASCII text
  $ echo hi > ../wt-test/.git/PR_BODY.md
  not a directory: ../wt-test/.git/PR_BODY.md
  ```
  `skills/end-chunk/SKILL.md` §4 writes `.git/PR_BODY.md`; §5 writes
  `.git/chunk-<id>-metadata.json`. Corroborating detail: the template `.gitignore`'s last
  line is `.git/PR_BODY.md` — an entry that can never match anything, because git does not
  track paths under `.git/`. The pattern was written by reasoning, never by running it.
- **Consequence** — the interactive lane's PR step fails inside any worktree; the
  unattended lane's would fail under the sandbox too. `forge-lane` §5 already does this
  correctly with `.forge/pr-body.md`, so the two skills disagree.
- **Correction** — move both to `.forge/` (already gitignored by convention in the lane) and
  make `.forge/` an explicit ignore in the template `.gitignore`.
- **Assert**
  ```bash
  ! grep -rn '\.git/PR_BODY\|\.git/chunk-' skills/
  grep -q '^\.forge/' templates/python-service/template/.gitignore
  ```

### F10 — `/roadmap` emits a nonexistent flag and the dependency graph is never built

- **Evidence (`measured`/`read`)** — `skills/roadmap/SKILL.md:52` prints `--body-file`;
  live `hermes kanban create --help` accepts `--body` only.
  `board-bootstrap.sh:100-103` **prints** link instructions rather than creating edges.
  Lines 91-94 silently `continue` past every `claude-interactive` chunk — and past nothing
  else, so a `forge-codex-lane` chunk that depends on a skipped interactive chunk becomes
  immediately dispatchable with its prerequisite missing.
- **Consequence** — downstream cards can run before their human prerequisites, and the
  operator rebuilds the graph by hand from ROADMAP prose.
- **Correction** — `/roadmap` emits `docs/chunks/*.md` **plus `docs/chunks/graph.json`**
  (`{id, lane, depends_on[]}`); `board-bootstrap.sh` consumes only `graph.json`, calls
  `kanban link` itself, and asserts the created edge count equals the declared edge count.
  Interactive chunks become real cards in `--triage` or `--initial-status blocked` — never
  silent skips, so their dependents cannot auto-promote.
- **Assert**
  ```bash
  ! grep -q -- '--body-file' skills/roadmap/SKILL.md
  jq -e 'length > 0' docs/chunks/graph.json          # in a roadmapped project
  # after bootstrap: edges created == edges declared
  ```

### F11 — Preflight validates the default profile while the lanes run somewhere else

*This is why F3 and F14 stayed invisible for a day. It deserves to be a finding, not the
eighth bullet of one.*

- **Evidence (`read`)** — `scripts/preflight.sh:250-290` reads `$HOME/.hermes/config.yaml`
  and bare `hermes config get`. Workers run under `~/.hermes/profiles/<name>/`, which
  `hermes-field-notes.md` itself documents as a separate `HERMES_HOME`.
- **Consequence** — a green preflight can coexist with two lanes that will die at
  `terminal.timeout` and a consent gate that is off. The tool reports on a profile nothing
  dispatches into.
- **Correction** — loop every profile named in `hermes kanban assignees`, read each with
  `hermes -p <name> config get`, and FAIL per profile. Keep the default-profile section, but
  label it as gateway config, not lane config.
- **Assert**
  ```bash
  ./scripts/preflight.sh --skip-llm | grep -c 'forge-codex-lane'   # must be > 0
  ```

### F12 — A prejudge bounce strands its own findings

- **Evidence (`read`)** — `forge-lane` §6 calls `kanban_complete` on the chunk card and
  creates the review card as a child. `forge-prejudge.SOUL.md:21` bounces via
  `kanban_block` on that child. ADR-0007's Consequences section already names this as its
  weakest decision.
- **Consequence** — the chunk card is `completed`, the review card is `blocked`, and the
  findings sit on a dead leaf. Nothing routes them to a worker, and no state machine
  encodes "bounce twice, then human".
- **Deliberately not recommended** — inventing a bounce loop. `hermes-field-notes.md`
  records a decision that bounce dynamics are board-native (respawn guard, `--max-retries`).
  The draft audit's "define retry/feedback" collided with that decision without citing it.
- **Correction** — the narrow fix ADR-0007 already anticipates: on bounce, prejudge
  `kanban_create`s a fix card assigned to `forge-codex-lane` with the findings verbatim as
  the body and `parents=[<chunk card>]`, then completes. Or adopt the ADR's stated fallback
  and have the lane `kanban_block(reason="review-required: …")` instead of completing.
- **Assert**
  ```bash
  grep -qE 'kanban_create|review-required' hermes/profiles/forge-prejudge.SOUL.md
  ```

### F13 — Ceremony skills collide with the Hermes worker lifecycle

- **Evidence (`measured`/`read`)** — `start-chunk` §3 runs `git switch -c chunk/<id>
  origin/main` inside a workspace the dispatcher already created **and already checked out
  on that branch** (F2) — the command fails. `end-chunk` §4 pushes and opens the PR,
  duplicating `forge-lane` §5. And both are live in the lane:
  ```
  $ hermes -p forge-codex-lane skills list --source local --enabled-only
  architect · end-chunk · forge-lane · judge · retro · roadmap · scope · start-chunk
  ```
  All eight are `enabled` for the unattended profile, not just `forge-lane`.
- **Consequence** — auto-invocation in the wrong layer branches, pushes, or completes twice.
- **Correction differs from the draft's** — do **not** add `disable-model-invocation`. That
  is a Claude-Code-only frontmatter key, and ADR-0002 commits the portable core to `name` +
  `description` only; adding it breaks a recorded decision to fix a Hermes problem. The
  Hermes-side control is stronger and already in use: `--skill forge-lane` force-loads
  exactly one skill (`hermes kanban create --help`). Scope which skills each profile's
  `external_dirs` exposes, and make `start-chunk` §3 branch only when not already on the
  chunk branch. `open-questions.md` already asks whether start/end-chunk should merge —
  resolve that first; it may delete this finding outright.
- **Assert**
  ```bash
  # `skills list` renders a rich table, so match the cell, not a bare word.
  ! hermes -p forge-codex-lane skills list --source local --enabled-only \
    | grep -qE '(start-chunk|end-chunk)'
  ```

## P2 — real, bounded, not urgent

### F15 — The Codex git-common-dir write is upgrade-fragile

*Demoted from the draft's P0. The draft called the behaviour "contradicted"; it is not.*

- **Evidence (`measured`)** — clean lab under `$HOME`, **not** `/tmp` (a probe under `/tmp`
  passes for the wrong reason — `workspace-write` grants `/tmp` and `$TMPDIR` unconditionally,
  which `hermes-field-notes.md` already warns about and which contaminated my first attempt):

  | invocation | result |
  |---|---|
  | `-s workspace-write`, no `--add-dir` | `fatal: Unable to create '…/.git/worktrees/wt/index.lock': Operation not permitted` |
  | `+ --add-dir "$(git rev-parse --git-common-dir)"` | commit succeeds; banner lists the dir as a writable root |

  `codex exec --help` documents `--add-dir` as *"Additional directories that should be
  writable alongside the primary workspace."* The lane is using a documented flag for its
  documented purpose. `hermes-field-notes.md` already records this correctly.
- **Consequence** — nothing today. The exposure is that a sandbox-policy change in a future
  Codex release breaks every unattended run *after* code has been written.
- **Correction** — keep the design; add the probe above to the conformance suite (S1) so an
  upgrade fails a check instead of a night run. The whole test takes ~30 seconds.
- **Assert** — the S1 case `codex/worktree-commit`, run after every `codex` upgrade.

### F16 — The pre-push guard is bypassable and no merge gate exists

- **Evidence (`read`)** — `templates/.../lefthook.yml` checks `git rev-parse
  --abbrev-ref HEAD`, so `git push origin HEAD:main` from a feature branch passes it;
  `--no-verify` bypasses it entirely. CI is not a merge gate without GitHub branch
  protection, which is not configured by `make new`. ADR-0007 D7.3's "auto-merge when
  approved AND low-risk" has no implementation anywhere in the repo.
- **Consequence** — trust in "green" is lower than the architecture diagram implies. Note
  this is currently moot: **F8 means the hook is not installed at all.**
- **Correction** — read the refs lefthook passes on stdin rather than the current branch;
  and, more importantly, have `make new` apply branch protection via `gh api` so the merge
  gate exists off the host. Mark D7.3 `planned`, not decided.
- **Assert**
  ```bash
  gh api "repos/$OWNER/$REPO/branches/main/protection" >/dev/null
  ```

### F17 — Preflight probe hygiene

- **Evidence (`measured`/`read`)** — probes have no timeout (a hung `claude -p` hangs the
  run indefinitely); success is `grep -qiw 'ok'` rather than structured output; probes load
  ambient harness config; `hermes kanban stats` (line 422) is a state-touching call in a
  tool labelled read-only.
- **Correcting the draft's evidence** — the draft states *"Codex lacks `--ephemeral`"*.
  It does not. `codex exec --help` on 0.145.0 lists **`--ephemeral`** ("Run without
  persisting session files to disk") **and `--ignore-user-config`**. The draft's own
  recommended fix is available today; only the Claude side needs a different approach.
- **Also correcting the draft** — `--out` truncating a path the operator explicitly passed
  is not a read-only violation. Dropping that claim strengthens the rest.
- **Correction** — wrap probes in a bounded timeout, add `--ephemeral --ignore-user-config`
  to the Codex probes, parse `--output-format json` for `is_error` instead of grepping, and
  split `--skip-llm` (pure inspection) from an opt-in `--probe` mode.
- **Assert**
  ```bash
  grep -q -- '--ephemeral' scripts/preflight.sh
  grep -qE 'is_error' scripts/preflight.sh
  ```

## Structural — what makes this durable rather than repeatedly re-audited

### S1 — Forge has no test for Forge. This is the finding.

`make validate` checks YAML frontmatter and `bash -n`. **Nothing in this repo executes a
single claim it makes.** Every finding above — F1's missing anchor, F3's timeout, F4's
missing schema, F5's `--body-file`, F8's absent hooks, F9's `.git` write, F14's consent
gate, F15's sandbox behaviour — is mechanically detectable in **under a minute**.

ADR-0003 says: *"If a rule MUST hold, it does not belong in a skill at all — move it down to
lefthook/CI. Skills persuade; gates enforce."* Forge has applied that to every project it
stamps and to none of itself.

**Build `make verify`** — an executable conformance suite, `Assert` blocks above as its
first cases, in four groups:

| Group | Asserts |
|---|---|
| `cli/` | every flag named in `skills/`, `hermes/`, and `docs/` exists in the live `--help` |
| `config/` | every documented invariant, read **per profile** (F3, F11, F14) |
| `substrate/` | throwaway-lab probes: worktree commit under sandbox, `.git` write denial, worktree ownership (F2, F9, F15) |
| `template/` | stamp → `make setup` → hooks installed → `make check` green (F8) |

Run it in this repo's CI, and as a hard gate after every `hermes update` and `codex`/`claude`
upgrade. That converts "prose debt" from a recurring audit finding into a build failure —
which is the only mechanism this repo has ever trusted for anything else.

The single highest-value property: **a claim that cannot be asserted may not appear in a
skill body**, because skill bodies are executed by machines that cannot tell aspiration from
observation.

### S2 — The flywheel proposes but never evaluates

`/retro` opens PRs against this repo and `write_approval` stages skill edits, but nothing
measures whether any change helped. There is no baseline and no metric, so the loop cannot
distinguish an improvement from a regression — it can only accumulate.

The exhaust already exists and is well-specified: `rubrics/kanban-metadata-schema.md` defines
`forge.chunk.v1` and `forge.block.v1`, and `forge.judge.v1` carries per-dimension scores.

**Correction** — define three numbers, recorded per retro period: bounce rate per chunk,
mean judge score on dimensions 1–3, and `reason_class` distribution from `forge.block.v1`.
`/retro` step 3 must state each proposed change's expected effect **on a named number**, and
step 1 of the *next* retro must open by reporting whether it moved. A proposal that cannot
name its metric is a preference, not a lesson.

**Assert** — `docs/retro-metrics.md` exists and gains a row per retro.
